The four patches

Each one stalls or corrupts a flow.
#Do thisWhenOtherwise
1 Create the wayfinder:* labels Before the first chart gh issue create --label fails outright — the issue is never created
2 Check your branch Before every /implement It commits to whatever you are on. It "does not create one, and it does not ask"
3 Commit, then review After /implement builds code-review reads <point>...HEAD, which excludes staged and working-tree changes — it reviews nothing and reports nothing
4 Close the ticket After every ticket The frontier never advances. Everything downstream stays blocked, silently
If you remember one

Close the ticket.

The other three produce a visible bad result. This one halts a multi-week build while every ticket still reads as blocked and nothing reports a problem.

Patch 4, as a frontier query

The frontier is every open ticket with no open blocker and no assignee. On GitHub the tracker template gives the mechanism — native issue dependencies, with issue_dependencies_summary.blocked_by reporting open blockers only, which is the live gate. That field is why closing matters: it is the only thing that moves a ticket onto the frontier.

Where a customisation has to live

Three places, one of which works.
PlaceVerdict
Editing a SKILL.md No. Read-only; overwritten on update
docs/agents/ via setup No. It configures three things only — "Config is death"
Your own CLAUDE.md, or the invocation Yes. Survives updates

Things to stop waiting for

Each is documented as absent. Planning around any of them is planning around something that does not exist.

  • implement closing a ticket, or ticking its criteria
  • implement opening a PR — "no configuration flag and no PR mode"
  • implement running more than one ticket, or several in parallel
  • tdd deciding whether a change is worth testing
  • tdd refactoring, despite its description saying so
  • code-review converging on a clean pass
  • research stopping on its own, or re-reading a past file
  • setup creating labels, holding preferences, or running at user level
  • A question cap on grilling — refused by policy
  • Anything at all firing a user-invoked skill on your behalf
