Flow chains

The five flows end to end, with the steps you have to insert yourself marked [ YOU ].

Every [ YOU ] line is a step no skill in the set performs. They are not optional and nothing will remind you — the omissions are collected separately in the manual patches.

1 — Small feature

Text Written for this reference

  v

  v

2 — Bug fix

Trigger: something broken, and it resisted a first glance.

Text Written for this reference 
(did someone else file it?)
  -> /triage                       verify -> agent brief -> ready-for-agent
  |
  v
/diagnosing-bugs
    Phase 1  tight, red-capable loop      <- HARD GATE: no theory before this
             red-capable / deterministic / fast / agent-runnable
    Phase 2  reproduce, then minimise     every element load-bearing
    Phase 3  3-5 ranked falsifiable       <- the ONLY checkpoint; will not block
    Phase 4  instrument, one variable     tag everything [DEBUG-xxxx]
    Phase 5  regression test first        ...if a correct seam exists
    Phase 6  cleanup; record the winner
  |
  v
[ YOU ] act on the "no seam" finding, if there was one
[ YOU ] commit
  |
  v
/code-review <fixed-point>         Spec axis may report "no spec available"

3 — Big feature

Trigger: decided, and the work spans several sessions.

Text Written for this reference 
/grill-with-docs   ──┐
/to-spec             │  ONE unbroken context window -- do not compact or clear
/to-tickets        ──┘  (seams agreed in to-spec step 2, for the whole feature)
                        (quiz: granularity / edges / merge or split?)
  |
  v
per ticket, blockers first:
    /clear                         each ticket is self-contained
    /implement #N                  one invocation, one ticket. no parallelism
    (commit)
    /code-review                   per-ticket: one clear spec per diff
    [ YOU ] close #N               <- or the frontier never advances
    [ YOU ] tick the criteria
  |
  v
/code-review <branch-point>        one final pass, for cross-ticket interactions

5 — Greenfield

Trigger: too big for one session and the way is not visible yet.

Text Written for this reference 
[ YOU ] create the wayfinder:* labels      gh issue create fails without them
  |
  v
/wayfinder                         CHART -- one session
    1 name the destination         grilling + domain-modeling
    2 breadth-first grill          NO FOG? stop. you did not need this flow
    3 create the map               wayfinder:map
    4 create tickets, THEN wire    two passes: ids must exist first
    5 fire /research subagents     research tickets resolve in parallel
    6 stop                         charting resolves nothing
  |
  v
/wayfinder <map>                   WORK -- one ticket per session
    load low-res -> claim (assign) -> resolve -> comment, CLOSE, point
    -> graduate fog / rule out of scope
  |
  v
map clear -> /to-spec #<map_issue>         <- hands off. does NOT build
  |
  v
then flow 3 from /to-tickets onward
