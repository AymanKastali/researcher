Skill index

All twenty-five promoted skills: who can fire each one, its exact trigger string, and what it drives.

Every description below is quoted verbatim from the frontmatter of the installed SKILL.md, because for a model-invoked skill that string is the trigger — what the agent matches your request against. Plugin 1.2.3, git 8b78b53.

Reading the Fire column

You means disable-model-invocation: true — only a human typing the name can reach it, and no other skill can. Either means the agent may also fire it on its own. Fourteen are You; eleven are Either.

Engineering — only you can fire these (9)

skills/engineering/, carrying disable-model-invocation: true.
Skilldescription:, verbatimDrives
ask-matt Ask which skill or flow fits your situation. A router over the skills in this repo. —
grill-with-docs A relentless interview to sharpen a plan or design, which also creates docs (ADR's and glossary) as we go. grilling, domain-modeling
to-spec Turn the current conversation into a spec and publish it to the project issue tracker — no interview, just synthesis of what you've already discussed. —
to-tickets Break a plan, spec, or the current conversation into a set of tracer-bullet tickets, each declaring its blocking edges, published to the configured tracker — edges as text in one file per ticket locally, or native blocking links on a real tracker. —
implement Implement a piece of work based on a spec or set of tickets. tdd, code-review
wayfinder Plan a huge chunk of work — more than one agent session can hold — as a shared map of decision tickets on your issue tracker, and resolve them one at a time until the way to the destination is clear. grilling, domain-modeling, research, prototype
triage Move issues and external PRs through a state machine of triage roles — categorise, verify, grill if needed, and write agent-ready briefs. grilling, domain-modeling
improve-codebase-architecture Scan a codebase for deepening opportunities, present them as a visual HTML report, then grill through whichever one you pick. codebase-design, grilling, domain-modeling
setup-matt-pocock-skills Configure this repo for the engineering skills — set up its issue tracker, triage label vocabulary, and domain doc layout. Run once before first use of the other engineering skills. —

Engineering — the agent can fire these too (9)

No disable-model-invocation flag.
Skilldescription:, verbatimSub-agents
grilling (in productivity/, listed here for the flow) Grill the user relentlessly about a plan, decision, or idea. Use when the user wants to stress-test their thinking, or uses any 'grill' trigger phrases. For facts
domain-modeling Build and sharpen a project's domain model. Use when discussing codebase terminology, writing or editing a CONTEXT.md, or recording or editing an ADR. no
codebase-design Shared vocabulary for designing deep modules. Use when the user wants to design or improve a module's interface, find deepening opportunities, decide where a seam goes, make code more testable or AI-navigable, or when another skill needs the deep-module vocabulary. yes, 3+
tdd Test-driven development. Use when the user wants to build features or fix bugs test-first, mentions "red-green-refactor", or wants integration tests. no
diagnosing-bugs Diagnosis loop for hard bugs and performance regressions. Use when the user says "diagnose"/"debug this", or reports something broken/throwing/failing/slow. no
code-review Review the changes since a fixed point (commit, branch, tag, or merge-base) along two axes — Standards (does the code follow this repo's documented coding standards?) and Spec (does the code match what the originating issue/spec asked for?). Runs both reviews in parallel sub-agents and reports them side by side. Use when the user wants to review a branch, a PR, work-in-progress changes, or asks to "review since X". yes, two
prototype Build a throwaway prototype to answer a design question. Use when the user wants to sanity-check whether a state model or logic feels right, or explore what a UI should look like. no
research Investigate a question against high-trust primary sources and capture the findings as a Markdown file in the repo. Use when the user wants a topic researched, docs or API facts gathered, or reading legwork delegated to a background agent. yes, background
resolving-merge-conflicts Use when you need to resolve an in-progress git merge/rebase conflict. no
wizard Generate an interactive bash wizard that walks a human through steps only they can perform. Use when provisioning infrastructure, setting up credentials or CI secrets, walking an unfamiliar third-party dashboard, or running a one-off migration or cutover. Don't invoke this for steps the agent can perform itself. no

Not shipped in the plugin

Ten further skills exist in the repository and none is reachable through the plugin, so none belongs in a plan. misc/ holds four "kept around but rarely used"; in-progress/ holds six beta skills, installable one at a time through skills.sh only; deprecated/ is empty by policy — "a retired skill is deleted, and the changeset that removes it names whatever replaced it."

Checking this yourself

Bash Written for this reference 
cd ~/.claude/plugins/cache/claude-plugins-official/mattpocock-skills/*/skills

for f in engineering/*/SKILL.md productivity/*/SKILL.md; do
  grep -q 'disable-model-invocation: true' "$f" && who=YOU || who=EITHER
  printf '%-7s %s\n' "$who" "${f%/SKILL.md}"
done | sort
