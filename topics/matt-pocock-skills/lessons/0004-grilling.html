Lesson 0004

Grilling

The interview primitive that five other skills run inside themselves. Sixteen lines long, and the only skill in the set with a contract binding both sides — what the agent owes you, and what you owe it.

More paths through this set pass through grilling than through anything else. Learn it once here and four later lessons get shorter, because they all say "and then it grills you".

Who reaches it

The router states the topology in one sentence, and it is worth holding because it explains why grilling itself is model-invoked while its two front doors are not:

The mechanism: a tree worked in rounds

Three things are being specified there at once, and it helps to separate them:

The three moving parts of a grilling session.
PartWhat it means
Design tree The shape of the problem. Decisions hang off decisions, so most questions are not askable yet
Frontier The subset askable right now — every decision whose prerequisites are settled
Round The whole frontier asked at once, then a hard stop until you answer

Even the question format is specified:

Markdown grilling/SKILL.md:12-16, verbatim 
❓ **Q1** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>

➡️ <your recommended answer>
Why every question carries a recommendation

That ➡️ line is not decoration. A frontier of eleven questions with no recommendations is an interrogation; the same eleven each carrying a proposed answer is a document you can approve in a word and argue with in three.

It is also the tell for a misfire. A session that asks everything at once with no recommendations attached is not running this skill — it is improvising an interview.

The contract: facts are the agent's, decisions are yours

This paragraph is the skill's real content:

The split, and what a violation looks like on each side.
Whose jobViolation
Facts The agent's, always "Which test runner does this repo use?" — it could have looked
Decisions Yours, always The agent picks, notes its own recommendation as settled, moves on

The second violation is named elsewhere in the tree in unusually blunt terms — "a grilling agent that answers its own questions has broken this" (wayfinder/SKILL.md:75). Not interpreted it liberally. Broken it.

The gate that ends it

Two separate conditions, and only one of them is automatic. An empty frontier is a state the agent can detect. A shared understanding is a claim you make, and nothing may proceed until you have made it. If a session slides from the last answer straight into building, the gate was skipped.

Which front door

Both wrappers run the same primitive. The difference is whether anything survives the session:

The choice, from ask-matt/SKILL.md:17 and :77.
/grill-with-docs/grill-me
State Stateful — writes CONTEXT.md and ADRs Stateless — saves nothing
Reach for it when You are in a working directory There is no repo under the subject
Subject Software, in a repo A plan, a design, a piece of writing — anything

The router does not present these as equals. Of /grill-with-docs: "it is strictly the better one" whenever a repo is there to leave a paper trail in.

The joint that slips

grill-with-docs is one line of prose delegating to two other skills, and in the version you have installed that delegation is documented as unreliable:

The working practice

When you type /grill-with-docs, check that the first round arrives numbered, in one batch, with a recommendation on every question. If it does not, say so: "did you load grilling and domain-modeling?"

This is the rough edge the unreleased rewrite in lesson 2 is intended to fix. Until the pin moves, it is yours to catch.

Why it never stops on its own

There is no cap on the number of questions, and that is a refusal rather than an omission. From the set's own record of things it has decided not to build: "A fixed cap would either cut off useful exploration on hard problems or feel arbitrary on easy ones." (.out-of-scope/question-limits.md)

So pacing is your lever, and it belongs in your own CLAUDE.md as a standing instruction rather than in the skill — which, being a read-only plugin install, would be overwritten anyway.

Check yourself

Mid-grilling the agent asks: "does this project use Vitest or Jest?" What is wrong?

Which runner a repo already uses is discoverable from the filesystem, so the skill requires the agent to dispatch a sub-agent and find out rather than spend your attention on it. Whether to switch runners would be a decision, and that one is legitimately yours.

Check yourself

The frontier is empty and the agent starts writing code. What was skipped?

The last sentence of the skill carries two conditions, not one: the frontier empties, and "the user confirms you have reached a shared understanding". The first is a state the agent observes; the second is a thing only you can say. Sliding from one into building skips the only gate the skill has.

What this sets up

/grill-with-docs is grilling plus a second skill running alongside it, writing things down as decisions land. That second skill has one rule about what its file may contain, and a three-part test for when to write anything at all: lesson 5.

Read next, from the source

skills/productivity/grilling/SKILL.md — all sixteen lines of it. It is the shortest high-value read in the whole set, and every sentence is load-bearing. Read it twice: once for the mechanism, once noticing how much of it is about what the agent is forbidden to do.

Your agent is your teacher. Worth trying: give it a half-formed idea and ask it to run grilling on you for exactly one round, then stop and explain which questions it left out of that round and why. The frontier is much easier to understand from the questions that were withheld than from the ones that were asked.

On spacing

Before moving on, state the facts/decisions split out loud and give one example of each from work you actually do. Then name the two conditions that end a session. The glossary has frontier defined in both its senses — the one here, and the ticket sense you meet in lesson 14 — and they are worth keeping apart.
