Lesson 0016

Charting a map

The heaviest flow in the set, for work too foggy to write a spec about. It produces decisions rather than deliverables — and it has an early exit that tells you it was the wrong choice.

Trigger: a greenfield project or a huge build, too big for one session, where the way from here to the destination isn't visible yet. That last clause is the real condition — not size, but fog.

What it is for, and the warning attached

Step 0 — create the labels by hand [synthesis]

This is the step that stops a first run dead, and it is the one place this topic tells you to run a command before anything else. Setup writes a label mapping, never labels — and gh issue create --label <missing> fails outright rather than creating one.

Bash Written for this lesson 
# Label names taken from issue-tracker-github.md's "Wayfinding operations":
# the map carries wayfinder:map, each ticket carries wayfinder:<type>.
for l in map research prototype grilling task; do
  gh label create "wayfinder:$l" --force
done
Why this is not optional

The docs page says it plainly: "Create them by hand before the first wayfinder run on a GitHub repo." The failure is not a warning and not a fallback — the issue simply is not created.

The map is an index

The map's fixed sections.
SectionHolds
## DestinationWhat this map is finding its way to
## NotesStanding instructions, including skills each ticket should use
## Decisions so farA gist and a link per resolved ticket — never the decision itself
## Not yet specifiedThe fog: questions you can see coming but cannot yet phrase
## Out of scopeConsciously ruled out of this effort

Open tickets are deliberately not listed — they are open child issues, found by query. And there is a presentation rule that reads like a detail and is not: "A wall of #42, #43, #44 is illegible; names read at a glance." Everything a human reads refers to tickets by title.

Fog, and the test that graduates it

Fog of war

The dim view of decisions and investigations you can tell are coming but can't yet pin down, because they hang on questions still open.

skills/engineering/wayfinder/SKILL.md:85.
The sentence to keep

State, not answer.

A question you can phrase precisely but cannot begin to answer is a ticket. A vague sense that "auth is going to be a problem" is fog. The instinct to tidy the fog into neat tickets is the thing the skill forbids.

Fog is distinct from out of scope, and the distinction is scope rather than sharpness: "Fog only ever gathers toward the destination." Out-of-scope work never graduates — it returns only if the destination is redrawn, and then as a fresh effort.

The four ticket types

Every ticket is either HITL — worked with a human who speaks for themselves — or AFK, driven by the agent alone. And the skill restates the grilling contract here, in its strongest form: "the agent never stands in for the human's side of it (a grilling agent that answers its own questions has broken this)."

skills/engineering/wayfinder/SKILL.md:77-80.
TypeModeUse when
Research AFK Knowledge outside the working directory is required. Resolved by a /research subagent
Prototype HITL "How should it look" or "how should it behave" is the question
Grilling HITL Conversation. The default case. Always invokes /grilling and /domain-modeling
Task Either Manual work that must happen before a decision can be made
Task is the type that goes wrong

It is "the one type that does rather than decides — and it earns its place by unblocking a decision, not by delivering the destination." Signing up for a service so its API can be judged; provisioning access; moving data so its shape can be seen.

The docs page: "This is the type that goes wrong most often in practice: agents interpret it as an implementation step and start writing product code inside the map."

Charting: six steps, and one of them is "stop"

Step 2's early exit is the honest one

If the breadth-first grill surfaces no fog, you did not need wayfinder. Drop back to the spec-and-tickets flow and you have lost one grilling session rather than a week.

Getting this exit is a correct outcome of running the skill, not a failure of it.

Two mechanical details worth holding: tickets are created then wired, in two passes, because issues need ids before they can reference each other — and charting resolves nothing. Step 6 is a full stop.

Check yourself

You know authentication will be difficult but cannot say what the question is. Ticket or fog?

The test is whether the question can be stated precisely now, and it cannot. A sharp-but-blocked question would be a ticket; this is not sharp. The skill also forbids pre-slicing fog into ticket shapes — a patch may graduate into several tickets later, or none.

Check yourself

Step 2's breadth-first grill surfaces no fog at all. What does that mean?

The skill builds the exit in: "the way to the destination is already clear, the whole journey small enough for one session — you don't need a map. Stop and ask the user how they'd like to proceed." Reaching it means the routing decision was wrong and you found out after one session instead of ten.

What this sets up

The map exists and nothing has been resolved. Working it is a different mode of the same skill, with a strict session rule and a hand-off at the end you must not skip: lesson 17.

On spacing

This is the densest lesson in the topic and it is worth a pause. Before moving on, state the fog test in four words, name the four ticket types with their HITL/AFK mode, and say what step 6 is. If only one survives, make it the fog test.
