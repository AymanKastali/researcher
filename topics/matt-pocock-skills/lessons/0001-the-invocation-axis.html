Lesson 0001

The invocation axis

One line of YAML splits the twenty-five skills into two populations that behave completely differently. Everything confusing about this set — and most of what looks broken in it — follows from that line.

Start here rather than with a workflow. A flow is a sequence of skill names, and until you know which names the agent can act on and which only you can, you cannot tell a step that was skipped from a step that was never runnable.

What a skill is

The set defines itself in one sentence, in a file written for its own maintainers rather than for users:

So a skill is a directory with a SKILL.md in it. The frontmatter names it and the body is the instruction. There is no code, no registration step, and nothing clever — which is why the one axis carries so much weight.

The two populations

The split, quoted from .agents/invocation.md:5-6.
User-invoked Model-invoked
Who can fire it Only the human typing its name The model or the user
Frontmatter disable-model-invocation: true The flag is simply absent
What description: is for A human reading a list of slash-commands. Trigger phrasing is stripped Matching against your request. Trigger phrasing is kept and tuned
Its job Orchestrate Hold reusable discipline

Here is the whole of one skill, so you can see how little there is to it:

YAML + Markdown skills/productivity/grill-me/SKILL.md, complete 
---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---

Run a `/grilling` session.

Four lines of frontmatter and one line of body. That flag on line four is the entire difference between a skill the agent will reach for and one it will never touch.

The invariant

This is the sentence to memorise. It is stated twice in the tree, once for maintainers and once in the public README, in nearly identical words:

The sentence to keep

A user-invoked skill can be fired by exactly one thing in the universe: you, typing its name.

Not the agent reasoning that it would be useful. Not another skill naming it. Not a chain that lists it as step three. You.

Which is which, counted from the files

Do not take this from a table someone wrote. The tree answers the question directly, and the command is worth running yourself the first time you doubt any of this:

Bash Written for this lesson 
# From the plugin root. Which skills can only you fire?
grep -l 'disable-model-invocation: true' \
  skills/engineering/*/SKILL.md skills/productivity/*/SKILL.md

# 14 of them. The complement -- the ones the agent can reach -- is 11.

Twenty-five promoted skills. Fourteen can only be fired by you. Eleven the agent can also reach on its own, and it is worth knowing them by name, because these are the only ones that will ever fire without you asking:

Why the split exists at all

It would be simpler to make everything model-invoked. The set declines to, and the reason is a budget:

"You are the index"

That phrase is the honest cost of this design, and it is the reason this topic exists. Fourteen skills have been deliberately made invisible to the agent so they do not eat context. The trade only pays off if you remember them — which is why lesson 7, the routing lesson, is the one that matters most.

The description is the trigger, not a summary

For the eleven model-invoked skills, one more thing follows. The description: string is not documentation about the skill — it is the matching surface the agent uses to decide whether to reach for it:

Compare the two styles in the actual frontmatter. The model-invoked one lists trigger phrasings on purpose; the user-invoked one has had them stripped, because nothing is matching against it:

YAML Both quoted from their SKILL.md frontmatter 
# model-invoked -- written to be matched against
description: Test-driven development. Use when the user wants to build
  features or fix bugs test-first, mentions "red-green-refactor", or
  wants integration tests.

# user-invoked -- written to be read by a human browsing a menu
description: A relentless interview to sharpen a plan or design.

The practical consequence is sharper than it looks: asking for "a relentless interview to sharpen my plan" will not fire /grill-me, because nothing is listening to that string. It may well fire grilling, whose description is written to trigger.

Check yourself

Which single line in a skill's frontmatter decides whether the agent can fire it on its own?

disable-model-invocation: true is the whole mechanism. The bucket folder decides whether a skill ships at all, and the description decides when a model-invoked skill fires — but only the flag decides whether it can.

Check yourself

grill-with-docs is user-invoked and its entire body reads "Run a /grilling session, using the /domain-modeling skill." Is that legal?

The invariant runs one way only: "A user-invoked skill may invoke model-invoked skills, but it can never reach another user-invoked skill." grilling and domain-modeling are both model-invoked, so the delegation is well-formed. Whether it works reliably is a separate question, and lesson 2 takes it up.

What this sets up

One axis, one flag, one invariant. Now apply it to the tree you actually have installed and three things fall out of it — one of which looks exactly like a broken installation and is not: lesson 2.

Read next, from the source

.agents/invocation.md in your own install, at ~/.claude/plugins/cache/claude-plugins-official/mattpocock-skills/1.2.3/. It is under thirty lines and it is the constitution of the whole set. Read it before any SKILL.md, because every skill is written on the assumption that you already have.

Your agent is your teacher. Worth asking: have it list every skill it can see from this set, then compare that list against plugin.json. The difference between the two lists is the subject of the next lesson, and watching it appear is much more convincing than being told about it.

On spacing

Before moving on, try to state the invariant out loud with no notes, and then name three skills on each side of the split. If the second half is hard, that is expected — the skill index is built for exactly that lookup, and the point is to notice which names you reach for it to find.
