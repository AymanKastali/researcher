Lesson 0012

Hypotheses and the fix

Four phases that consume the loop from lesson 11 — containing the only checkpoint in the skill, one instruction that makes cleanup a single grep, and a finding you are allowed to return instead of a fix.

By the skill's own account these phases are "mechanical". That is true of their difficulty, not their content — three of the four contain a rule that changes the outcome.

Phase 3 — hypothesise, plural, and falsifiably

The sentence to keep

If you cannot state the prediction, it is a vibe.

"It might be a race condition" makes no prediction and rules nothing out. "If it is a race between the cache write and the read, adding a 10ms sleep before the read will make it disappear" can be run in a minute and is worth having.

The only checkpoint in the skill

Worth knowing before you walk away

This is the only point in six phases where the skill pauses for you — and it explicitly does not block. If you are away, it takes its own ranking and proceeds.

Which makes this the moment to be present for. Your re-ranking is usually the cheapest information in the entire session.

And one instruction that solves a problem most debugging leaves behind:

# Every probe carries the same session-unique tag.
log.debug("[DEBUG-a4f2] cache read  key=%s hit=%s", key, hit)
log.debug("[DEBUG-a4f2] cache write key=%s ttl=%s", key, ttl)

# Cleanup is then one command, and it cannot miss one:
#   grep -rn "DEBUG-a4f2" .
The performance branch

"For performance regressions, logs are usually wrong. Instead: establish a baseline measurement (timing harness, performance.now(), profiler, query plan), then bisect. Measure first, fix second."

A slow system instrumented with logs tells you what ran, never what took the time.

Phase 5 — the regression test, and the seam that may not exist

That middle paragraph is a permission most debugging processes do not grant. A test at the wrong seam is worse than no test, because it will pass forever while the bug pattern remains reachable.

When the seam does exist, five steps, in order:

Text skills/engineering/diagnosing-bugs/SKILL.md:124-128 
1. Turn the minimised repro into a failing test at that seam.
2. Watch it fail.
3. Apply the fix.
4. Watch it pass.
5. Re-run the Phase 1 feedback loop against the original (un-minimised) scenario.

Step 5 is the one people drop. The minimised repro is not the bug the user reported — it is a stripped-down cousin of it. The original scenario is what has to come back green.

Phase 6 — cleanup, and a checklist item about the future

SKILL.md:134-138 — required before declaring done.
Check
Original repro no longer reproduces — re-run the Phase 1 loop
Regression test passes, or absence of seam is documented
All [DEBUG-…] instrumentation removed — grep the prefix
Throwaway prototypes deleted, or moved somewhere clearly marked
The hypothesis that turned out correct is stated in the commit or PR message — so the next debugger learns

The last one is the only item on the list that costs nothing now and pays someone else later. It is also the one no tooling can check.

Check yourself

Phase 5 finds that the only available test seam cannot reproduce the bug pattern. What now?

"If no correct seam exists, that itself is the finding. Note it. The codebase architecture is preventing the bug from being locked down." A test at a seam that cannot exercise the real bug pattern gives false confidence — which is worse than an honest gap. Refactoring may well follow, but after the fix is in, not instead of the finding.

Check yourself

Why does Phase 3 require three to five hypotheses rather than the best one?

Quoted exactly: "Single-hypothesis generation anchors on the first plausible idea." The requirement is a debiasing device, not a throughput one — the probes still change one variable at a time, and each must map to a specific prediction.

skills/engineering/diagnosing-bugs/SKILL.md — all six phases, about 140 lines. It is the longest skill in the set and the most self-aware; read it noticing how many sentences exist to stop the agent doing the natural thing. That ratio is what makes it work.

Your agent is your teacher. Worth asking at Phase 3 on a real bug: "give me the ranked list, and for each one tell me the prediction and how you would falsify it in under a minute." The cheap-to-test ones should move up the ranking regardless of how likely they are, and that is a judgement worth practising together.
