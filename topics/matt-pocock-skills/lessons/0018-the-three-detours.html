Lesson 0018

The three detours

What to do when a session stalls on a question that cannot be settled by talking. Three skills, three different shapes of missing answer — and picking the wrong one wastes the whole detour.

Trigger: you are mid-grilling, mid-map, or mid-spec, and a frontier question will not resolve. The diagnosis is not "this is hard" — it is what kind of answer is missing.

The triage

Three shapes of missing answer.
What's missingWhere it livesReach for
A judgement you cannot make on paper In something you would have to see running /prototype
A fact about the outside world In documentation, a spec, someone's source code /research
A decision that is not yours to make In another person's head /to-questionnaire

Detour one — /prototype

Two branches, and the skill warns that "getting this wrong wastes the whole prototype":

prototype/SKILL.md:14-15.
QuestionArtifact
"Does this logic / state model feel right?" One shareable HTML file — free-play buttons plus tabbed guided walkthroughs, driveable by a non-developer
"What should this look like?" Several radically different variants on one route, switched by a URL search param and a floating bar

The UI branch carries the rule that makes it worth doing at all: "Variants must be structurally different — different layout, different information hierarchy, different primary affordance, not just different colours. Three slightly-tweaked card grids isn't a UI prototype, it's wallpaper."

And the logic branch keeps the logic in a pure module: "If the pure module references the DOM, document, or button handlers, it's no longer liftable." The page is a thin shell; the module behind it is the part worth keeping.

"Throwaway" constrains how it is written, not what happens to it

"Fold any validated decision into the real code, then capture the prototype itself as a primary source: commit it to a throwaway branch, out of main, and leave a context pointer to that branch on the implementation issue. Capture the answer too — the verdict and the question it settled […] The main branch keeps only the validated decision."

So: no tests, no error handling, no abstractions — and it is kept, on a branch, pointed at from the issue. Both halves.

The other anti-patterns are worth reading as a group, because each names a way of accidentally building production code: "Don't add tests. A prototype that needs tests is no longer a prototype." · "Don't generalise. No 'what if we wanted to support X later.'" · "Don't reach for a framework, bundler, or server." · "Promoting the prototype directly to production […] Rewrite it properly when you fold it in."

Detour two — /research

The entire skill, which you have already seen the output of — this topic's source document was produced by it:

The background agent is the point: "Keep working while it reads." Which is exactly what grilling requires — a running exploration is an unsettled prerequisite, so only the questions downstream of it wait.

Three known costs

It can spawn a duplicate of itself. An open bug: "One reporter measured a single research task costing roughly 450k tokens across three overlapping runs."

It has no stopping criterion. "There is no stopping criterion in the skill… Scoping is on you."

Nothing ever reads the file again. "Nothing auto-loads a past research file; it is a document sitting in the repo until a human or a skill points at it."

The router adds the routing rule for what to do with the file: "The file it produces is something to take into the main flow at /grill-with-docs — research feeds the thinking, it doesn't replace it."

Detour three — /to-questionnaire

The sentence to keep

Grill the send, not the subject.

You are stuck precisely because you cannot answer questions about the subject. So it asks you two things you can always answer — who is this going to, and what do you need back — and aims the document at the gap between them.

It writes to-questionnaire-<slug>.md in the current directory, questions ordered most-important-first because "async means you may only get one pass". Run it in the same conversation that stalled — it has no ingest step, so a fresh session knows nothing about the thread.

The bridge: /handoff, in both directions

A prototype lives in its own directory, which is precisely the situation question 3 of the phase-boundary tree is for. The router spells out the round trip:

/handoff writes to the OS temporary directory — "not the current workspace" — includes a suggested skills section, and carries two rules that make the document worth reading: "Do not duplicate content already captured in other artifacts (specs, plans, ADRs, issues, commits, diffs). Reference them by path or URL instead." and "Redact any sensitive information."

Check yourself

You cannot decide whether a three-state or five-state machine is right. Which detour?

The missing answer is a judgement you cannot make on paper, which is the logic branch exactly: a single HTML file that "pushes the state machine through cases that are hard to reason about on paper". The UI branch answers a different question and would produce the wrong artifact — which the skill warns "wastes the whole prototype".

Check yourself

Why must /to-questionnaire run in the stalled conversation rather than a fresh one?

Its three steps interview you about the send and then draft against the subject — but nothing in it fetches or reads the thread that stalled. A fresh session would know the recipient and need, and nothing about the actual gap. The current-directory detail is true and is not the reason.

What this sets up

One lesson remains, and it is the one that makes the rest safe to rely on: what this set does not do, how to tell when a skill has misfired, and the four things you must always do yourself. Lesson 19.

Read next, from the source

skills/engineering/prototype/LOGIC.md — the fullest specification of an artifact anywhere in the set: what the panel shows, how the walkthroughs are tabbed, why the logic must stay liftable. It is also the clearest demonstration of how much of a good skill is spent describing the output rather than the process.

Your agent is your teacher. Worth practising: next time a decision stalls, ask it to name which of the three shapes of missing answer you are facing before proposing anything. The diagnosis is the skill here; the detour follows from it mechanically.

On spacing

Before the last lesson, state the three detours by what is missing rather than by skill name — a judgement, a fact, a decision that is not yours. That framing is what makes the choice automatic.
