Topic

The Matt Pocock Skills, and Choosing Between Them

Twenty-five skills, five flows, and one measurement that settles most of the routing — read out of the installed plugin tree at a pinned commit, including the six instructions inside it that cannot execute.

Nineteen lessons, built to be spaced over days rather than read in one sitting. Lessons 1–6 are the machine and its primitives; lesson 7 is the hinge — the routing decision the whole topic is arranged around; 8–17 are its five branches worked through; 18–19 are the detours and the judgement. The five reference documents at the bottom are the ones built to be returned to.

What is pinned here

Everything is read from plugin 1.2.3, git 8b78b53 (2026-08-13), on disk. That matters more than usual: the public repository is 34 commits ahead while reporting the same version string, so "1.2.3" identifies nothing on its own. Lesson 2 is about exactly this.

Part one — the machine

  • 0001 The invocation axis

    One line of YAML splits the set into two populations that behave completely differently. Fourteen skills only you can fire; eleven the agent can reach. Everything confusing about this set follows from that line.

  • 0002 Reading your install honestly

    Three things no write-up will tell you: half the skills are invisible to the agent, six instructions inside them cannot execute, and the version number identifies nothing.

  • 0003 What setup writes

    The one skill to run before any engineering flow — and the silent wrong default you get if you skip it, which is not an error and looks exactly like success.

Part two — the primitives

  • 0004 Grilling

    Sixteen lines that five other skills run inside themselves. The design tree, the frontier, and the only contract in the set that binds both sides: facts are the agent's, decisions are yours.

  • 0005 Domain modelling

    One prohibition about what the glossary may contain, and a three-part test that correctly produces no decision record most of the time.

  • 0006 Phase boundaries

    Five things you can do with a context window, one ordered tree, and the reason the option most people reach for first sits at the bottom.

Part three — the hinge

  • 0007 Choosing the flow

    The lesson the topic is built around. One measurement decides almost everything — and it is not size, difficulty, or importance. Plus the floor below which no skill is the right answer.

Part four — the five flows

  • 0008 The small feature loop

    Three skills, one context window, and two steps you must insert yourself — including the one that otherwise commits your feature onto the main branch.

  • 0009 TDD and the seam gate

    The only place a build stops and hands control back. Plus the three bad tests the skill names, and the step its own description promises that it does not contain.

  • 0010 Code review's two axes

    Two sub-agents that must never see each other's findings, a report you are forbidden to merge, and a loop that will never come back clean.

  • 0011 The Phase 1 gate

    One skill refuses to think about your bug until it can make the bug fail on demand. Ten ways to build that instrument, and the four properties it must have before anything else may happen.

  • 0012 Hypotheses and the fix

    Four phases that consume the loop — the only checkpoint in the skill, the tag that makes cleanup a single grep, and a finding you are allowed to return instead of a fix.

  • 0013 To-spec

    A skill whose first instruction is to not ask you anything — and which quietly contains the step where a whole feature's test seams get agreed.

  • 0014 To-tickets

    Slices that each land green, edges that declare what blocks what, and a quiz step that exists because this skill fails in two specific, predictable ways.

  • 0015 Working the frontier

    One ticket, one fresh window, one commit — repeated. Plus the single missing step that stops the frontier advancing, which is the most load-bearing gap in the whole set.

  • 0016 Charting a map

    The heaviest flow, for work too foggy to write a spec about. Fog versus ticket, four ticket types, and an early exit that tells you it was the wrong choice.

  • 0017 Working a map

    One ticket per session, recorded in three places — and a hand-off you must not skip, because skipping it throws away everything the map was for.

Part five — detours and judgement

  • 0018 The three detours

    What to do when a session stalls on a question talking cannot settle. The diagnosis is not "this is hard" — it is what kind of answer is missing.

  • 0019 When the set has misfired

    Every flow has a way of looking like it worked when it did not. The tells, the four things you must always do yourself, and the one judgement nothing in the set will make for you.
