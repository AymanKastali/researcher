Lock and rewrite ledger

What each PostgreSQL 16 operation locks, whether it rewrites, and who therefore waits. The lookup table for “is this migration safe?”

Everything here is from the PostgreSQL 16 manual. Where a subform names no lock, the documented answer is ACCESS EXCLUSIVE — the ALTER TABLE Description states the default, so silence is an answer rather than a gap.

No longer on this list

ALTER TYPE … ADD VALUE. Relaxed in PostgreSQL 12; since then the restriction is only that “the new value cannot be used until after the transaction has been committed”. Advice predating 12 still circulates widely.

Finding an invalid index

SQL Written for this reference 
-- Every invalid index in the database.
SELECT c.relname AS index_name, t.relname AS table_name
FROM pg_index i
JOIN pg_class c ON c.oid = i.indexrelid
JOIN pg_class t ON t.oid = i.indrelid
WHERE NOT i.indisvalid;

-- Documented alternative: psql reports it as INVALID.
--   \d tab   ->   "idx" btree (col) INVALID

-- Documented recovery: drop and retry.
DROP INDEX CONCURRENTLY idx;

indisvalid: “False means the index is possibly incomplete: it must still be modified by INSERT/UPDATE operations, but it cannot safely be used for queries. If it is unique, the uniqueness property is not guaranteed true either.” — 53.26. pg_index

Timeouts

From 20.11.2. Statement Behavior.
Setting What it does The catch
lock_timeout Aborts a statement waiting too long for a lock. Default 0 = off Applies separately to each lock acquisition attempt, so a multi-relation statement can wait N × the value. Must be below any nonzero statement_timeout or it never fires
idle_in_transaction_session_timeout Terminates sessions idle inside an open transaction The systemic fix for both the convoy and stalled concurrent index builds — it removes what DDL queues behind
The convoy — cite MySQL, never PostgreSQL

A waiting ACCESS EXCLUSIVE request blocks requests queued behind it, including ones that do not conflict with the lock currently held. PostgreSQL’s manual never states this.

The citable source is MySQL 8.0 17.12.2: “a pending exclusive metadata lock requested by an online DDL operation blocks subsequent transactions on the table” — used by analogy, and labelled as one.
