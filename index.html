Transactional Outbox

Taking the pattern from the dual-write problem to operating it in production. Read them in order the first time — each one ends by deferring something the next picks up. After that, the glossary is the page to come back to.

  2. Lesson 02 The Message Relay The table, the claim query, and the one design decision the whole relay turns on.
  3. Lesson 03 At-Least-Once and the Idempotent Consumer Where every duplicate comes from, and the one transaction boundary that makes them harmless.

Idempotency Keys

4 lessons1 referencecited, never run

What a server must do when a caller retries a POST it never got an answer to. Four lessons from the one failure the network cannot resolve, through what you store and who a key belongs to, to the handler that has to survive a call it cannot take back.

  1. Lesson 01 The Key and the Server's Algorithm One failure the network cannot resolve, one string that resolves it, and the four steps a server runs when the same string arrives twice.
  2. Lesson 02 What You Store, and For How Long The fingerprint, which failures get cached and which don't, and the 500 whose stored answer stays wrong on purpose.
  3. Lesson 03 The Key Across a Trust Boundary Scoping the key — an access-control problem your handler never sees, and the decision that quietly defines what "the same request" means.
  4. Lesson 04 Foreign State Mutations When the work inside the transaction is a call you cannot take back: atomic phases, recovery points, and the handler as a state machine.
  5. Reference The Idempotent POST Handler The algorithm, the decision table and the vocabulary on one printable page.
